The tabs live in an AppKit `NSToolbar` inside `ChalkAppKitGlue`, a runtime-loaded bundle no test target links.
What the `stripIs*`/`stripLeading*` rules assert is the app's half of that contract — the divider inset, visibility and fade the app DECIDED and posts to the glue (recorded at the post sites, before the scene-bound gate) — checked against `MacStripExpectation.forState`.
Whether the glue draws what it was told is pinned only as pure functions by `TitlebarBandGeometryTests`; nothing asserts the drawn result.
The same holds for the accent underline: `activeUnderlineTracksTheActiveName` sees the UIKit row (full screen), and the AppKit row's underline is pinned by ChalkKit's `ThemePalette` and `TabStripMetrics`, which the glue compiles in, not by this matrix.

## The rules

### `bandSpansFullWidth`

The tab row's opaque cover is one surface across the whole window. It stops nothing and reads as nothing (Paper paints it in the editor's own tone), but it has to span: a cover that ends at the sidebar divider lets full-bleed text surface beside the names, and a cover that ends anywhere else draws an edge across the paper.

### `bandPaintStaysInsideTheBand`

The band's opaque region never extends past the band itself. Paint escaping below it draws a line across whatever sits underneath.

### `libraryIsNeverPaintedOver`

The Library panel keeps its own surface. The band runs behind it, which means the panel is cut out of the paint rather than drawn over.

### `outlinePanelIsNeverPaintedOver`

The outline panel keeps its own surface, like the Library: the band runs behind it, so the panel is cut out of the paint on the trailing edge rather than drawn over. A band across its top hides the panel's header under the chips.

### `nameRowClearsTheLibrary`

The tab names start at the editor column. A name over the Library would sit on a surface it does not belong to, even though the cover behind it spans the window.

### `restingLineSitsOneLineBelowTheReserve`

The document's first line rests one editor line below whatever chrome reserves space above the text: the tab band where it is hosted, the system titlebar on a windowed Mac, and nothing at all in zen, where the text rises to the top pad.

### `pillRestsInTheCorner`

The utility pill rests at the same corner offsets in every state, zen included: since Paper it is the ONLY home for the chrome buttons (the Library holds files and nothing else), so it never hands off, never hides, and a pill that drifts with a chrome transition reads as a control that wanders.

### `editorContentFillsTheColumn`

The editor's content column reaches the window's trailing edge and starts at the Library divider while the Library is tiled, at the safe-area leading edge otherwise; a column pinned to a stale edge moves every line of text, not just the first. With the outline panel pushed open the column ends at the panel's leading edge instead; in overlay mode it keeps the window edge and the panel floats over it.

### `libraryListStartsAtTheChromeFloor`

The Library's first area header begins on the line the system titlebar ends on. The band is the titlebar, which spans the whole window, so the Library has nowhere to go but below it — the two columns start their content together on that line.

### `libraryPanelReachesTheWindowEdges`

Paper's Library is flush: its surface runs to the window's leading, top and bottom edges. A panel that stops short reads as a floating card again — which is the treatment the direction removed.

### `activeUnderlineTracksTheActiveName`

The accent underline sits under the ACTIVE tab's label, spanning exactly it, one fixed gap below. It is the only mark that says which document you are in now that the chip is gone, so an underline that outruns its label, misses it, or lingers under the previous one is the tab row lying about the state.

### `stripLeadingTracksTheDivider`

The windowed Mac tab chips start at the Library divider while the Library is tiled and return to the traffic lights when it hides; a stale inset leaves the tabs floating over the panel or parked mid-window after it closed.

### `stripVisibilityMatchesTheState`

The titlebar strip's toolbar stands exactly when the state calls for it: full screen hands the tab row to the UIKit band, and zen keeps the toolbar standing while the chips fade. A recorded visibility that disagrees with the mode is a titlebar lying about the state — or a window that collapsed its content area in zen.

### `stripFadeMatchesTheState`

Outside zen the fade belongs to an active auto-hide scroll run only — a strip still faded in a normal resting state is the stale-fade handover bug (TabChromeOwnership) wearing a new state. Zen's FADE lane is the one state that RESTS faded (the faded, glue-hidden strip is the zen titlebar), so an un-faded strip standing over zen fails the same rule from the other side.

### `bandAndStripNeverBothCarryTheTabs`

One tab row, ever. The row moves between the app's UIKit band and the AppKit titlebar strip (TabChromeOwnership), and a handover that shows the new owner without quieting the old one puts the same tabs on screen twice — which is what the owner photographed on 2026-08-24: entering full screen hid the strip, the auto-hide re-application then posted an un-fade, and the un-fade un-hid it, so the revealed system titlebar carried a second tab row above the band.

### `chromeStaysInsideTheWindow`

No chrome element hangs outside the window's bounds, which is how an off-screen column or a clipped strip first shows up.

### `outlinePanelReachesTheWindowEdges`

The outline panel is the Library's mirror on the trailing side: flush with the window's trailing and bottom edges. A panel that stops short reads as a floating card, which is the treatment the palette already has and this panel exists to replace.

### `outlinePanelSharesTheEditorTop`

The panel starts where the editor's content column starts: full-bleed under the transparent titlebar. A panel pinned to the safe area instead opens a dead strip above it.

### `outlinePanelModeFollowsTheWidthFloor`

The panel pushes the editor while the column can spare the width and overlays it once the text would drop below the readable floor. The floor is the metrics table's number, so a panel that pushes a 300pt column or overlays a 900pt one is applying the wrong rule.
