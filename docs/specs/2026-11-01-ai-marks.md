# AI marks

Text written to an open file from outside Chalk is tinted until the user accepts it or edits it.
Two uses share this one rule: reviewing an agent's changes, where you accept them, and a discussion sheet, where the AI asks and you answer, and the marks stay as the record of who said what.

## Behaviour

- Any outside write is marked. macOS gives Chalk no cheap way to know which process wrote a file, so `git pull`, iCloud and other editors count too. Settings > Mark Outside Writes turns marking off.
- First load, tab reuse, crash recovery and saves from another Chalk window are not marked.
- Typing inside a mark splits it. Your text is never marked.
- Removed text shows as a tick. Hovering any mark offers Accept and Reject for that mark, plus the old text if it replaced some.
- A rewritten sentence is one mark: a kept shard no longer than the edits around it joins them, within one original line.
- AI text replacing unaccepted AI text leaves no tick, and Reject still restores the original human text.
- Accept (Cmd+Shift+Return) keeps the text. Reject (Cmd+Shift+Delete) removes it and restores what it deleted.
- Both act on marks the selection touches, whole marks, or on all marks with no selection. Both undo with Cmd+Z.
- View > Show AI Marks hides the tint without losing the marks.
- Marks survive quitting. Text changed while Chalk was closed is marked on reopen, if the file already had marks.

## Limits

- Mac only. VS Code gets the engine but never sends `origin`: it can't yet tell a disk write from a sibling pane.
- Marks live in Chalk's folder (`AiMarks/`, a JSON file per marked document with a copy of its text), so they don't travel with the file.
- A rename inside Chalk keeps marks. One outside Chalk loses them.
- A file with no marks gets none for edits made while Chalk is closed: no record exists to compare with.
- A GFM table cell edit replaces the whole table, so it clears the table's mark.
- A write that lands in the last 150 ms of typing before quit can leave the record slightly behind the disk, and that difference is marked on reopen.

## How it fits together

- `update` gains optional `origin: 'external'`, which is the only thing that adds marks. `init` and `update` gain optional `aiMarks`, so restored marks keep FIFO order with their text. `HostPort` stays at 9 message types.
- The engine diffs an `origin` update itself (`word-diff.ts`), which covers both Mac paths, clean buffer and `TextMerge`, with no change to the merge.
- On load, the host seeds the record's text with its marks, then sends the disk text as an `update`. So one code path maps marks through a difference, with no diff in Swift.
- The editor owns marks while open and pushes them, debounced, over the transport-internal `ai-marks` message. `ProvenanceStore` owns them while closed.
- `OwnSaves` remembers recent saved text by hash, which is how another window's save is told apart from an outside write. Its stat baseline can't do that: the file really did change.
